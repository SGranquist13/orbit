## Known traps (each cost real debugging time)
- **package.json scripts run in Bun's shell:** `\` is an escape there (and `\t` in JSON is a tab), so script paths use forward slashes (`scripts/tauri.cmd`).
- **Phone can't connect?** Windows Firewall: Orbit's exe gets its own prompt when Settings > Mobile is turned on (allow on Private). A `node.exe` with inbound Block rules on Public networks also blocks Expo/mock-orbit for the phone.
- **Toolchain:** `scripts/cargo.cmd` / `scripts/tauri.cmd` load MSVC through `scripts/vcvars.cmd` (cl.exe on PATH, else `VCVARS`, else vswhere preferring VS 2022, whose x64 libs are known to work). Build Rust through them from bash. Voice input (whisper-rs) also needs **CMake and LLVM** (`winget install Kitware.CMake LLVM.LLVM`); `vcvars.cmd` finds both. The crate's bundled bindings are Linux-layout and fail on MSVC, so libclang is required; after changing that environment run `cargo clean -p whisper-rs-sys` (its build script result is cached).
- **e2e needs Vite on :1420** (`bun run dev` or the `ui-mock` launch config) because the debug build loads its UI from it. New npm imports make Vite re-optimise and force-reload the page on first load: rerun if the first e2e step dies with "Execution context was destroyed". **Don't open `localhost:1420` in another browser (e.g. the Claude browser pane) while e2e runs:** the harness can attach to that page instead of the app and fails with "not running inside Tauri (mock?)".
- **e2e scratch must be outside any git repo.** `git rev-parse --show-toplevel` from a "plain" folder inside the Orbit checkout resolves to Orbit itself, so editable attachments created real worktrees of this repo (`.e2e/` used to live here). `resolveScratch` in `scripts/e2e-harness.mjs` defaults to the OS temp dir and aborts otherwise; a single step (`node scripts/e2e.mjs <step>`) runs after the cheap prerequisites and fails fast with "needs the full suite" when it depends on earlier steps' workspaces.
- **Agent binaries are resolved by identity, not by name.** `bun run` puts every ancestor `node_modules/.bin` on PATH, and an ancestor `package.json` can pull in an unrelated npm package named `codex` (e.g. a docs generator that exits 0), so the first PATH hit can be the wrong program. `process::resolve` for `codex` / `claude` walks PATH hits then the vendors' own locations (Codex app build, `~/.codex/.sandbox-bin`, VS Code extension, global npm/bun) and accepts the first whose `--version` matches (`codex-cli …` / `… (Claude Code)`); candidates in a `node_modules/.bin` without the official package are skipped. The verified path is cached per run; Settings > Agents shows it or the error. A session that fails to start ends the turn with an error instead of leaving the UI waiting.
- **Native dialogs can't be clicked over CDP and Tauri's `invoke` is non-writable**, so confirmations in e2e go through `window.__ORBIT_AUTOCONFIRM__` (harness `autoConfirm()`, honoured by `src/lib/confirm.ts`).
- **UI state persists between e2e runs** (WebView2 localStorage in the scratch dir's own `webview2` profile, e.g. Ship panel open; the harness sets `WEBVIEW2_USER_DATA_FOLDER` so e2e can run while your own Orbit is open). Use the harness helpers (`ui.openShip()`, race-free `ui.newWorkspace()` that waits for the new workspace) instead of toggles.
- **GitHub checks:** third-party apps (e.g. CodeRabbit) add statuses (a `StatusContext` with `state`, not `status`/`conclusion`). Judge CI by the sandbox's own `check` job.
- **Agents use judgement:** asking an agent to create a CI-breaking file and then "fix CI" fails because it rightly refuses to undo its own requested work. Simulate breakage from a teammate commit instead.
- **Ctrl+Shift+I opens WebView2 DevTools** in dev builds, so it can't be an app shortcut (Issues uses Alt+5).
- **Token counts exclude cache reads** (every API call re-reads the cached conversation). "Tokens" = input + output + cache writes.
- **Sessions carry a generation** (`SessionHandle.generation`); an `Exited` event only forgets its own session. Keep that invariant when touching session lifecycle.
- **Read-only must be enforced, not prompted.** Claude read-only = `--permission-mode default` + allowlist (a denylist alone lets `echo > file` through Bash). New sessions after a profile switch need the `role_notices` hand-over note or the resumed agent keeps its old role.
- **Merge resolution:** parallel agents in worktrees conflict mostly on `mock.ts`, `Palette.tsx` imports, and placeholder files; both sides are usually wanted (union).
- Shell scripting from bash: apostrophes and backticks inside `node -e '…'` break quoting. Write a temp .cjs script instead. Codex briefs with apostrophes break the same way: pass them with `codex-companion.mjs task --prompt-file`.
- **ConPTY asks for the cursor position (`ESC[6n`) before it emits any output.** xterm.js answers in the app; anything else driving a PTY (tests) must reply `ESC[1;1R` or it sees nothing.
- **The app-wide `::selection` paints text in the accent ink**, which hides text on CodeMirror's drawn selection. The Code theme sets `color: currentColor` on `.cm-content ::selection` (`inherit` picks up the parent's highlight colour in Chrome).
- **Codex can write non-ASCII characters (…, —, curly quotes) as Windows-1252 bytes** inside UTF-8 files. tsc and `bun test` read them leniently and pass; `vite build` fails with "stream did not contain valid UTF-8". Run `bun run build` after Codex edits UI files.
- **Codex's sandbox has no network:** it can't `bun add` or fetch crates. Install new dependencies in the worktree before handing off, and compile/test Rust yourself afterwards.

## Working with Codex (second coding agent)
Claude orchestrates; Codex (through the Claude Code `codex` plugin) is a second pair of hands for fixes and features, on its own subscription, so it saves Claude usage.
- **Setup:** `npm install -g @openai/codex`, `codex login`, then `/codex:setup` in Claude Code (must report ready). The plugin needs `codex` on PATH; Orbit itself finds Codex elsewhere (see Known traps), so the app working does not mean the plugin will.
- **Hand off** with the `codex:codex-rescue` agent (or `/codex:rescue`): a self-contained brief naming files, the bug/feature, constraints from this file, and how to verify (`scripts\cargo.cmd test`, `bun run check:guards`, `bunx tsc --noEmit`). Ask for `--write` and always an explicit model:
  - `gpt-6.1-sol`, effort `medium`: default for fixes and features (`low` for small, fully specified fixes).
  - `gpt-6-luna`: mechanical edits only (renames, text, config).
  - `gpt-6-astra`: only for a genuinely hard bug. It is the default in `~/.codex/config.toml`, so leaving out `--model` silently uses it.
- **Codex cannot commit** (its sandbox can't write `.git/index.lock`): it leaves changes uncommitted; the orchestrator reviews the diff, commits it (no co-author trailers: commits carry only the maintainer's name), and runs the e2e.
- **Don't run Codex and another writer on the same files.** Use an isolated worktree for parallel work, and never junction `node_modules` from a worktree to the main checkout (force-removing that worktree deletes the real `node_modules`; repair with `bun install --force`).
- Good fits: well-specified bugs with a repro, Rust/TS fixes with unit tests, config/CI. Keep design calls, UI taste and e2e diagnosis with Claude.

## Commands
- `bun run app` — run the desktop app (wraps `tauri dev` with the MSVC toolchain via `scripts/vcvars.cmd`).
- `bun run dev` then open http://localhost:1420 — **UI-only mode with a mock backend** (`src/lib/mock.ts`). Fastest loop for UI work; verify visual changes here.
- `bunx tsc --noEmit` — typecheck UI.
- `bun run e2e` — drives the **real** desktop app (debug build + `bun run dev` running) via WebView2 remote debugging, with real agents in a scratch repo under `<os tmpdir>/orbit-e2e` (isolated `ORBIT_HOME`; override with a path arg, which must be outside any git repo: the harness checks). Add a step to `scripts/e2e.mjs` for every user-facing feature. **Keep e2e cheap:** every Claude turn uses `model: "haiku"` (and any model setting a step touches, e.g. `simplifyModel`, is set to haiku for the step), prompts are one-line tasks with a one-word or one-sentence answer, and no step needs more than one or two agent turns. Run it as a background command and watch the log (a `Monitor` grep for `✗|steps passed|EXIT`): that costs no model use. A Haiku runner works for one-shot runs but is poor at waiting on a 20-minute job. Diagnose and fix separately; the e2e state db (`<tmp>/orbit-e2e/home/state.db`, table `events`) holds each workspace's events for post-mortems.
- `bun run e2e:github` — opt-in GitHub e2e (Ship, CI, merge, Fix CI, issues, write-ticket, preflight) against a private sandbox repo (`ORBIT_GH_SANDBOX`, required unless gh is logged in as the maintainer; the sandbox's CI fails if a `FAIL` file exists). Creates and closes real PRs/issues there.
- **`PLANNING.md` holds feature ideas being discussed.** Record ideas there and iterate with the user; don't build them until they're agreed and added to the FEATURES.md roadmap.
- **`VERIFICATION.md` (local) is the source of truth for how each feature is proven; `FEATURES.md` is its public summary.** When you build or verify a feature, update both: a new feature is 🧪 Preview in FEATURES.md until it works in the real app, then ✅ Available.
- Rust: `cmd //c "scripts\\cargo.cmd test"` (or `build`) from bash; it wraps the VS 2022 toolchain. Add `-- --include-ignored` for live tests against real agent CLIs.

## Releases
**Rule: code reaches `main` only through a release.** Many branches land on `next`; a release consolidates `next` into `main` with a tag, a GitHub release and a README showcase. Never merge a feature or fix branch straight to `main`, and never leave a version bump without its tag and release. The `/release` skill (`.claude/skills/release/SKILL.md`) is the checklist; use it whenever the user asks to release, cut or ship a version.
- **Branches:** `main` = the latest release (what the README's Download link installs). `next` = the integration branch for the coming release. Feature and fix branches start from `next` and merge back into `next` after their own e2e step passes. Docs-only changes (README, FEATURES, PLANNING) may go straight to `main`; merge `main` back into `next` after them.
- **Changelog as you go:** every user-facing merge into `next` adds a line under `## Unreleased` in `CHANGELOG.md`, in the public tone of FEATURES.md (🧪 features say "Preview:"). Unreleased starts with a one-sentence summary paragraph; `bun run release` copies it into the README's "New in" line.
- **Versions:** semver on 0.x: a minor (`0.3.0`) ships features, a patch (`0.2.1`) only fixes. The version lives in `package.json`, `tauri.conf.json`, `Cargo.toml` and `Cargo.lock`; only `bun run release` changes it. (The `shipkit` pack versions separately in its `plugin.json`.)
- **Cadence:** cut a release when a set of features on `next` is done, or about every two weeks when Unreleased has something worth shipping. An urgent fix for the released version: branch from `main`, merge it to `main` as a patch release, then merge `main` into `next`.
- **A release:** full `bun run e2e`, `bun run e2e:github` and `cargo test` on `next` (ask the user first: see Known traps), `bun run release X.Y.Z`, merge `next` into `main`, annotated tag `vX.Y.Z`, push `main`, `next` and the tag. Pushing the tag runs `.github/workflows/release.yml`: it checks the tag against `package.json`, builds the NSIS installer and creates a **draft** GitHub release with that version's changelog section. Smoke-test the installer, then publish the draft so it becomes "Latest".

## Architecture
- `src/lib/keybindings.ts` — pure command registry, effective bindings, context resolution and chord dispatcher. `keybindingRuntime.ts` registers app handlers; `lib/code/keymap.ts` generates live CodeMirror bindings. Settings `keybindings` stores full-map overrides, including empty arrays to unbind.
- `src-tauri/src/agent/` — each agent CLI is driven over stdio and normalized into `AgentEvent` (`mod.rs`). **The UI never sees agent-specific shapes.**
  - `claude.rs`: `claude -p --input-format stream-json --output-format stream-json …`, one long-lived process per workspace; interrupt = stdin `control_request`.
  - `codex.rs`: `codex app-server` JSON-RPC; mid-turn messages use `turn/steer`. Protocol types: `codex app-server generate-ts --out <dir>`.
  - `process.rs`: spawns windowless children and scrubs host Claude env vars (`CLAUDECODE`, `CLAUDE_CODE_*`, …) — without this, launching from inside a Claude session breaks child auth.
- Parsers are pure functions tested against `src-tauri/tests/fixtures/*.jsonl`. When an agent's output format changes, **record a real stream into a fixture first**, then fix the parser.
- `skills.rs` — skill packs in `~/.orbit/packs/<name>` (standard Claude plugin layout; installed by git URL). Skill id = `<plugin>:<folder-or-file-stem>`; this matches what Claude registers (it ignores frontmatter `name`). Claude runs skills natively (`--plugin-dir` + `/<id> args`). Codex can't load foreign skills (its `{type:"skill"}` input only resolves skills in its own registry), so `expand()` inlines them.
- `src-tauri/shipkit/` — the bundled shipping pack (embedded via `include_str!`, rewritten to `packs/shipkit` on startup). Commands read branch/base/issue from the workspace context prompt (`workspace_context` in `lib.rs`: Claude `--append-system-prompt`, Codex `developerInstructions`), not template variables, so they stay portable markdown.
- Profiles: `shipkit/agents/*.md` (Claude agent format + Orbit keys `agent`, `readonly`, `skills`), listed by `skills::list_profiles`, appended to `workspace_context` as "Your role". Read-only is enforced, not just prompted (Claude: `--permission-mode default` + the `READONLY_ALLOW` allowlist; Codex: read-only sandbox). Switching profile queues a one-shot hand-over note (`role_notices`) for the next message.
- Attachments (`related.rs`, `attachments` table): extra folders passed to Claude as `--add-dir` and listed in the context prompt; editable ones get their own worktree.
- **Never call a helper that locks `db()` inside an expression that already holds `state.db()`.** `std::sync::Mutex` isn't reentrant, so the command deadlocks. Bind the result first. This also covers `match state.db()… {}` / `if let … = x.lock()… {}` (the guard lives to the end of the block, edition 2021): `#![deny(clippy::significant_drop_in_scrutinee)]` in `lib.rs` makes `bun run check:guards` (clippy) fail on it; run it after touching db/lock code.
- `settings.rs` — typed app settings, one JSON blob under `settings.app_settings` (`get_settings` / `update_settings`; Ctrl+, opens the page). Add a field there, in `ipc.ts`, and in `src/components/settings/`; wire it to behaviour (no dead toggles). `maintenance.rs` holds `environment_info` and merged-worktree cleanup.
- `routines.rs` — scheduled messages ("every Monday at 9", "once tomorrow 3pm", cron as the Advanced escape hatch). `next_after` is pure (zone-agnostic core `next_core` with an injectable local-time resolver, so DST gap/fold are unit-tested). A 30s tokio tick (`routines::start`, spawned in `run()` setup) runs due routines through `create_workspace_inner` + `send` / `run_skill_with`; missed runs run once on launch; `once` switches itself off; concurrency cap = `routineConcurrency`. Completion is hooked in `on_agent_event` (`finish_turn` / `finish_exited`): the run row is finished synchronously, then a clean fresh run with no changes is marked `quiet` and archived (`archive_inner`, UI told via `workspace-archived`). Routine runs defer their desktop/phone notification until that quiet check. Tables `routines`, `routine_runs`, `workspaces.routine_id`; UI in `Routines.tsx` (also the chat's clock-button popover and `WhenControl`), `lib/routines.ts`; the mock has its own `previewTimes`. Action `simplify` (editor "What" selector): `run_simplify` runs `simplify::run_unattended` (Find over `Scope::Since { days: 7 }`, apply the low-risk candidates), then `prepare_ship_inner` + `shipkit:ship`; the workspace is on a `refactor/` branch (`NewWorkspaceArgs.branch_prefix`). Its own edit turns end in `TurnCompleted` too, so `finish_turn` swallows them via the per-workspace `Stage` and only the ship turn (or `run_simplify` itself when nothing was applied) finishes the run. `finish_run_with` is the single finish path: row first, then quiet/notify, then `refine_summary` (`Task::RoutineSummary`, async, updates the row; `nothingToDo` + no changed files can still flip a fresh run to quiet).
- Usage: `AgentEvent::Usage` (emitted just before `TurnCompleted`; Claude from the `result` line + last assistant usage, `compact_boundary` resets context; Codex from `thread/tokenUsage/updated`), aggregated in `usage.rs`; UI in `ContextMeter.tsx` and `settings/UsageSection.tsx`. `compact_session` / `new_session` free context (`AgentEvent::SessionReset` marks a new session).
- `teammates.rs` — AI teammates (PLANNING #10; UI in `Teammates.tsx`: the Teammates view (nav item, view `teammate`: list + thread) and the editor with its avatar picker; avatars are `TeammateAvatar.tsx` + `lib/avatar.ts`, `avatar: shape:colour[:expression]`). A teammate is a markdown definition (`shipkit/teammates/*.md` embedded in `BUNDLED`, custom ones in `~/.orbit/teammates/<slug>.md`; a same-slug custom file overrides a starter, deleting it resets) plus `<slug>.memory.md`. `teammate_send` decides new task vs continue (`decide`, pure), picks the repo (`pick_repo`, pure; ambiguity errors with "Pick a repository…" and the UI asks), creates the workspace through `create_workspace_inner` with `NewWorkspaceArgs.teammate` (column `workspaces.teammate`) and sends the message through the normal `send`. `context_section` (name, instructions, reporting protocol, memory path + last 4 KB) is appended to `workspace_context` in `ensure_session`; Claude also gets the teammates dir via `--add-dir`; `readonly` = teammate's own flag, else its profile's. `on_agent_event` calls `teammates::on_user_message` (reopens a done/waiting task when you type in its workspace) and `teammates::finish_turn` on `TurnCompleted`: only a task that is `running` reports; an error or stop is posted at once, a finished turn goes through `report` (`llm::Task::TeammateReport`, fallback = the agent's last message) into `teammate_messages` and the task becomes `done` / `waiting` (a question keeps it open for the next message). Status per teammate = `derive_status` (working > needs you (waiting task or report newer than `teammate_seen:<slug>`) > idle); UI refreshes on the `teammate-changed` event. Teammate threads feed the inbox as their own rows (`Reason` `teammate` is only the tone/label), not through `attentionReason`. **Phase 2:** `start_task` / `adopt_task` (shared by direct messages, Chief parts, hand-offs and owned routines) take an `Origin` (`teammate_tasks.parent_task_id` / `origin_kind` chief|handoff|routine / `origin_ref`) and either post the user's message or a `brief` entry. `chief.rs`: messaging Chief (slug `chief`, a bundled starter) runs `Task::ChiefPlan` through `llm::complete_json` (not an agent session) and stores a plan in `teammate_plans` (parts as JSON, `status` planning|proposed|running|done|cancelled|failed; shown as a `plan` message card); `chief_plan_start` runs it and `advance` (serialised by a static async mutex, called from `teammates::report` / `finish_turn` through `chief::task_changed`) starts every part whose dependencies are `done`, posts failures once, and posts the combined report (`Task::TeammateReport`) when all are done. Pure and tested: `parse_plan` (drops unknown slugs, remaps `dependsOn`, rejects cycles), `startable`, `progress`, `derive_status`, `dependency_brief`. `handoff.rs`: `default_chips` (rules by role = profile name, else slug), `workspace_plan` (Reviewer: worktree from the branch tip via `NewWorkspaceArgs.start_ref`; Shipper / fixes after a review: same workspace via `adopt_task` + `switch_profile` when the agent matches), `handoff_brief`; `teammate_tasks` returns `TaskView` (row + chips + `handedTo`). Routines: `routines.teammate`; `launch` calls `launch_via_teammate` for an owned message routine (`owner_of`, `check_owner`).
- `remote/` — mobile bridge for the companion phone app (`ide_mobile`; contract in its `docs/protocol.md`). `server.rs` is Orbit-agnostic (WebSocket on `0.0.0.0:<remotePort>` path `/v1`, handshake, boxed frames, broadcast `Hub`, device list through the `Backend` trait) and tested with a fake backend; `mod.rs` holds the Orbit backend (RPC allowlist calling `send` / `db` directly), `apply()` (start/stop from settings at startup and in `update_settings`), and the `remote_*` commands; `crypto.rs` is `crypto_box` SalsaBox (tweetnacl-compatible, vector-tested); `push.rs` posts Expo pushes (name + status only). Hooks: `on_agent_event` / `emit_workspace` call `remote::publish_*`, so the phone sees what the desktop UI sees. Keypair and devices live in `settings` keys `remote_keypair` / `remote_devices`; pairing codes are in memory only. UI: `settings/Mobile.tsx`.
- `code/` — the Code view's backend (PLANNING #12; UI `src/components/code/`, store `src/stores/code.ts` (`useCode`), helpers `src/lib/code/`, IPC `codeApi` / `ptyApi` / `codeEvents` in `ipc.ts`). Every command takes a `root` + forward-slash `rel` and goes through `resolve_inside` (rejects absolute paths, `..` escapes, symlink escapes). `fs.rs`: list/read/write (`expected_mtime` → `conflict:` error, never a silent overwrite)/create/rename/delete (recycle bin via `trash`)/list files/`code_file_at` (HEAD or merge-base with base). `watch.rs`: ref-counted `notify` debouncer per root → `code-fs` events (skips `.git`, `node_modules`, `target`). `search.rs`: `ignore` walker + grep-searcher, 2,000-match cap, generation-cancelled. `pty.rs`: portable-pty shells (`terminalShell` setting, host env scrubbed like agents) → `pty-data` / `pty-exit`; all killed on app exit. Live agent edits are frontend-only: `src/lib/code/agentEdits.ts` maps `agent-event` tool calls (Claude `Write`/`Edit`/`MultiEdit`/`NotebookEdit`, Codex `Edit` `files`) to paths; `useCode` keeps per-turn baselines, the activity timeline and mode per root (`watch` follows the agent and is read-only while it runs; a mode the user picked is `modePinned`, so turns don't flip it back). `toolDraft` feeds separate live typing previews; changes without drafts use a bounded typing replay before settling from disk. `agentMarks.ts` (flash + agent gutter) and `gitGutter.ts` are CM extensions.
- `voice/` — voice input (PLANNING #14). The microphone lives in the webview (`src/lib/voice/mic.ts`, `getUserMedia` with echo cancellation, so the mic can stay open while Orbit speaks); Silero VAD (`@ricky0123/vad-web`) segments hands-free speech; the hands-free loop is the pure `hfReduce` in `src/lib/voice.ts` driven by `src/stores/voice.ts`. Rust only transcribes: `voice_transcribe` (base64 f32 16 kHz → whisper-rs → `stt::is_junk` → optional `Task::VoiceTidy`), plus sha-pinned model downloads (`models.rs`: Whisper .en models, the Kokoro pack) and `voice_file` (allowlisted pack bytes as raw IPC). Read-aloud: Kokoro-82M in onnxruntime-web workers (`src/lib/tts/`, G2P from misaki's lexicons, never espeak-ng: GPL) or Windows `speechSynthesis`. Threaded wasm needs cross-origin isolation (COOP/COEP in Vite `server.headers`, the `/speech/` asset middleware, and `app.security.headers`). e2e feeds `scripts/fixtures/voice-pong.wav` through Chromium's fake capture device.
- `simplify.rs` — the Simplify pass (PLANNING #8; `SimplifyPanel.tsx`, header button, palette entry). Orbit drives the loop, prompts are embedded in Rust. Find: one-shot enforced-read-only `claude -p` (`--tools Read,Grep,Glob`, `--json-schema`, prompt via stdin) over the diff vs base. Apply: per candidate it records HEAD, `send`s a focused turn to the workspace's own session and waits for its `TurnCompleted` (`on_agent_event` calls `simplify::on_event`), then `finish_step` decides (`decide_step`, pure: touched tests / check result / no-op) and commits `refactor:` or `reset --hard` + `clean`. While Apply runs `simplify::active` makes `trunk::save_point` skip its `wip:` commit, and Apply requires a clean tree (it commits a save point first, or refuses when save points are off). State is in-memory statics keyed by workspace id, pushed to the UI as `simplify` events. Settings: `simplifyModel`, `simplifyMaxCandidates`, `simplifyLowRiskButton`. `Scope::Diff` (the button) vs `Scope::Since { days }` (files changed on base in a window, used by the Simplify routine); `begin_find` / `find_and_record` / `begin_apply` are shared by the commands and `run_unattended`.
- `trunk.rs` + `checks.rs` — trunk-based git handling as app logic (no view of its own; surfaces through the inbox, palette and Settings > Git). `on_agent_event` spawns `trunk::save_point` after each `TurnCompleted` (`wip:` commit), `prepare_ship` runs the check command (`checks::detect` / `run`, per-repo override in `repos.check_command`) then squashes unpushed `wip:` commits, `trunk::start` is the background fetch + rebase loop (`sync_one`, `sync_action` decide per `syncMode`), `after_merge` archives and syncs overlapping workspaces. Workspace fields `checks_failed` / `sync_conflicts` / `behind` / `ahead` feed the inbox reasons in `attention.ts`. All of it is switchable in `settings.rs` (`saveCommits`, `squashWip`, `checksMode`, `syncMode`, …). Mutating git calls take `trunk::GIT_LOCK`; never rebase a running workspace. `checks::run` takes `RunOptions` (timeout from `checkTimeoutMinutes`, kills the process tree; one-time dependency install from `installBeforeChecks`) and returns a `CheckKind` (pass / fail / timedOut / installFailed). `commitMessages = model` makes `save_point` ask `Task::CommitMessage` (staged stat + capped diff, bounded by `localTimeoutSecs`, `choose_message` falls back to the prompt-derived `wip:` message; the git lock is never held across the call). `prepare_ship_inner` (shared with the Simplify routine) drafts a PR title/body with `Task::PrDescription` only when that task is a `local:` model and returns it as `notes` for `shipkit:ship`'s argument.
- `llm.rs` — all utility model calls (suggestions, workspace names, commit messages, routine summaries, PR drafts) go through `llm::complete_json(state, Task::…, system, prompt, schema)`; never call `claude -p` directly for utility work. Each task is set to Default (Claude), `local:<model>` (Ollama or an OpenAI-compatible server) or Off in Settings > Models; local failures fall back to Claude for required tasks and skip optional ones. Experimental local agents use workspace model `local:<name>` (`agent::local_model`): Claude gets `ANTHROPIC_BASE_URL` pointing at Ollama, Codex gets `-c model_provider="ollama"`.
- `gh.rs` — PR status/checks/merge via the `gh` CLI.
- `lib.rs` — Tauri commands + `on_agent_event` (persist → update status → notify → emit `agent-event` / `workspace`).
- `src/lib/ipc.ts` mirrors the Rust types; keep them in sync (serde uses camelCase).
- Attention inbox: `db.rs` keeps per-workspace `seen_seq`/`dismissed_seq` and builds `Summary` rows; `src/lib/attention.ts` (pure) decides why a workspace needs you and the rule suggestions; `suggest_prompts` in `lib.rs` adds AI suggestions via a one-shot `claude -p --model haiku --tools "" --json-schema …`.
- `src/lib/transcript.ts` folds events into render blocks (consecutive tool calls → one collapsible group).

## Conventions
- **Colour is reserved for function.** Chrome is greyscale (dark "Void" by default, light "Paper" via Ctrl+K Ctrl+T; `data-theme` on `<html>`, `src/lib/theme.ts`). Hues only carry meaning: `run` (working), `ok` (done / additions), `bad` (error / deletions), `warn`, `info`, `merged`. `accent` is the neutral emphasis ink (white on dark), not a brand colour. Never add decorative colour. **One deliberate exception (user, 2026-10-12): teammate avatars** are cute colourful blob faces (`avatar-*` tokens); status still lives in dots, never in the avatar colour.
- Chat bubbles (your messages) are the one softly rounded element: `rounded-[16px]` with a 5px tail corner, `bg-hover` + `border-line`. Never white/inverted blocks.
- **All UI text is Inter** (400 body, 500 UI labels, 600 headings; `tabular-nums` for numbers). JetBrains Mono only for literal code: code blocks, inline code, tool commands/paths, tool output. Never `font-mono` on chrome (labels, chips, keys, badges). Keep weights restrained; no font-bold in UI chrome. Small radii (3–6px), 1.5px borders, hard offset shadows (`shadow-hard`, `shadow-hard-sm`).
- Use the theme tokens (`bg-panel`, `text-mute`, `border-line-strong`, `bg-run`, …), never raw hex in components.
- Dither (`src/lib/dither.tsx` + `.dither-*` utilities in `index.css`) is a 1-bit Bayer mask; colour comes from the element's background (`bg-run` for running sweeps/progress, `bg-line-strong` for rules). Use it for rules, the selected-row fade, running sweeps, and progress, never behind body text.
- Brand mark: `src/assets/orbit.png` (the user's dithered black hole). `OrbitMark` (ui.tsx) for small sizes, `OrbitHero` for the start page (planet orbiting, passes behind the horizon). `.orbit-art` blends it onto either theme. App icons: `bunx tauri icon src/assets/orbit.png -o src-tauri/icons`.
- Every new action gets a palette entry (`Palette.tsx`); frequent ones get a shortcut.
- Agents run unattended in their worktree by default (Claude `bypassPermissions`, Codex `never`/`danger-full-access`); Settings > Agents can tighten this to Accept edits / workspace-write. Read-only profiles are always enforced regardless.
